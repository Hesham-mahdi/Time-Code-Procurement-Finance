# نظام ربط المشتريات بالمالية — Time Code
### وثيقة المتطلبات وخطة التنفيذ (مسودة للاعتماد)

---

## 1. الهدف
موقع واحد يجمع مدير المشتريات والمالية على نفس البيانات:
- المشتريات ترفع فواتير وعروض أسعار كل مشروع وتطلب سدادها.
- المالية تسدد، ترفع إيصال السداد، والنظام يبلّغ المشتريات تلقائياً.
- النظام يحسب **مركز التكلفة** لكل مشروع ويقارن **التكلفة التقديرية** (العرض المالي) بـ **التكلفة الفعلية**.

---

## 2. المستخدمين والصلاحيات

| الدور | يقدر يعمل إيه |
|---|---|
| **مدير المشتريات** | إنشاء مشروع · رفع فاتورة ضريبية / عرض سعر · تحديد نسبة السداد المطلوبة · رفع الفاتورة الضريبية بعد السداد · متابعة حالة طلباته |
| **المالية** (مدير النظام) | كل ما سبق مشاهدةً · رفع العرض المالي التقديري للمشروع · اعتماد / رفض / استيضاح طلب السداد · تسجيل الدفعات وإرفاق إيصال السداد · تقارير مركز التكلفة · إدارة المستخدمين |
| **الإدارة** (اختياري) | مشاهدة فقط: لوحة التحكم والتقارير |

---

## 3. دورة العمل (Workflow)

```
[المشتريات] إنشاء مشروع
      │
[المالية] رفع العرض المالي التقديري (الميزانية)
      │
[المشتريات] رفع مستند ──► النوع: فاتورة ضريبية  أو  عرض سعر
      │                   + المورد + المبلغ + نسبة السداد المطلوبة % + صورة المستند
      ▼
  🔔 إشعار للمالية: "طلب سداد جديد"
      │
[المالية] مراجعة ──► رفض (مع السبب) ──► 🔔 إشعار للمشتريات
      │           └► استيضاح ──► 🔔 إشعار للمشتريات
      ▼
[المالية] تسجيل دفعة: المبلغ / النسبة + التاريخ + طريقة الدفع + ⬆ إيصال السداد (إلزامي)
      │
  🔔 إشعار للمشتريات: "تم السداد" + الإيصال مرفق
      │
      ├── لو المستند "فاتورة ضريبية" وتم سداد 100% ──► ✅ مكتمل
      │
      └── لو المستند "عرض سعر" ──► الحالة: ⏳ بانتظار الفاتورة الضريبية
                │                    🔔 تذكير للمشتريات برفع الفاتورة الضريبية
                ▼
          [المشتريات] رفع الفاتورة الضريبية مربوطة بعرض السعر
                │
                ▼
          ✅ مكتمل (عند سداد 100% + وجود الفاتورة الضريبية)
```

### حالات المستند
| الحالة | المعنى |
|---|---|
| جديد | اترفع ولسه المالية ما شافتهوش |
| قيد المراجعة / استيضاح | المالية بتراجع أو طالبة توضيح |
| مرفوض | مع سبب الرفض |
| مسدد جزئياً | فيه دفعة أو أكتر، والمسدد أقل من 100% |
| مسدد بالكامل | المسدد = 100% من قيمة المستند |
| بانتظار الفاتورة الضريبية | عرض سعر اتسدد ومحتاج فاتورة ضريبية |
| مكتمل | مسدد + فاتورة ضريبية مرفقة |

### قواعد السداد
- **نسبة السداد المطلوبة** يحددها مدير المشتريات عند الرفع (مثلاً 50% دفعة مقدمة).
- المستند الواحد يقبل **أكتر من دفعة** (مقدم ثم باقي)، والنظام يحسب تلقائياً:
  `نسبة المسدد = إجمالي الدفعات ÷ قيمة المستند` · `المتبقي = القيمة − المسدد`.
- ممنوع تسجيل دفعة تخلي المسدد يتعدى قيمة المستند (تحذير).
- إيصال السداد إلزامي لكل دفعة.

## 5. مركز التكلفة والمقارنة

لكل مشروع يحسب النظام:

| المؤشر | طريقة الحساب |
|---|---|
| **التكلفة التقديرية** | من العرض المالي اللي ترفعه المالية (إجمالي + توزيع على البنود) |
| **التكلفة الملتزم بها** | مجموع كل المستندات المعتمدة (فواتير + عروض أسعار) |
| **التكلفة الفعلية المسددة** | مجموع الدفعات الفعلية |
| **المتبقي للسداد** | الملتزم بها − المسددة |
| **الانحراف** | التقديرية − الملتزم بها (بالقيمة والنسبة) |
| **نسبة استهلاك الميزانية** | الملتزم بها ÷ التقديرية |

**منع التكرار:** لما الفاتورة الضريبية تترفع مربوطة بعرض سعر، قيمتها **تحل محل** قيمة العرض في الحساب (مش تتجمع عليه)، ولو فيه فرق بين المبلغين النظام يعلّم عليه.

**العرض:**
- جدول مقارنة لكل بند: تقديري · ملتزم · مسدد · انحراف · نسبة.
- ألوان: 🟢 أقل من 90% من الميزانية · 🟡 90–100% · 🔴 تجاوز.
- رسم بياني تقديري مقابل فعلي لكل بند.
- تقرير شامل لكل المشاريع في جدول واحد.
- تصدير Excel / طباعة PDF.

## 6. الصفحات

1. **تسجيل الدخول**
2. **لوحة التحكم** — حسب الدور: طلبات معلقة، مبالغ مستحقة، مشاريع متجاوزة للميزانية، آخر الإشعارات
3. **المشاريع** — قائمة + إنشاء مشروع (الاسم، الكود، العميل، الموقع، تاريخ البدء، الحالة)
4. **صفحة المشروع** — تبويبات:
   - المستندات (فواتير وعروض أسعار وحالاتها)
   - الدفعات والإيصالات
   - العرض المالي التقديري
   - مركز التكلفة والمقارنة
5. **رفع مستند** (المشتريات)
6. **تسجيل دفعة** (المالية)
7. **طلبات السداد** — كل الطلبات المعلقة عبر كل المشاريع مع فلترة
8. **الإشعارات** — جرس في أعلى الصفحة + صفحة كاملة
9. **التقارير** — مقارنة كل المشاريع + تصدير
10. **الإعدادات** — المستخدمين، بنود التكلفة، نسبة الضريبة

الواجهة: **عربي بالكامل (RTL)**، العملة **ريال سعودي**، تعمل على الموبايل والكمبيوتر.

## 7. التقنية المقترحة

| الجزء | الاختيار | السبب |
|---|---|---|
| الواجهة | HTML + CSS + JavaScript بدون أدوات بناء | تشتغل مباشرة على GitHub Pages ومش محتاجة تثبيت أي حاجة |
| الاستضافة | **GitHub Pages** من الريبو `Time-Code-Procurement-Finance` | مجانية ورابط ثابت |
| قاعدة البيانات + الدخول + الملفات + الإشعارات اللحظية | **Supabase** (الخطة المجانية) | GitHub Pages بيستضيف صفحات بس — محتاجين خادم يحفظ البيانات ويشاركها بين المشتريات والمالية |
| الصلاحيات | Row Level Security في Supabase | المشتريات ما تقدرش تسجل دفعة، وكل دور يشوف المسموح له بس |

> ⚠️ GitHub Pages وحده مينفعش: البيانات لازم تكون مشتركة بين جهازين (المشتريات والمالية) والإشعارات لازم توصل للطرف التاني — ده محتاج قاعدة بيانات أونلاين.

### الجداول
- `profiles` — المستخدمين ودورهم
- `projects` — المشاريع
- `budget_items` — بنود العرض المالي التقديري لكل مشروع
- `documents` — الفواتير وعروض الأسعار (مع ربط الفاتورة الضريبية بعرض السعر)
- `payments` — الدفعات
- `attachments` — كل الملفات (مستندات، إيصالات، عروض مالية)
- `notifications` — الإشعارات
- `cost_categories` — بنود التكلفة
- `activity_log` — سجل مين عمل إيه وإمتى
